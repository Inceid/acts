# Preamble
The **kernel** of an operating system comprises a set of operations that has complete control over the system and communicates among its components. Think of the kernel as the chief executive officer of the operating system, and its operations as forming a core component of the constitution of that system. 

`pivot: council` In the setting of [[Internal Governance]], the **kernel** comprises the constitution and law of `RI` as agreed and enforced by the [Council](<The Council>).

`pivot: mind` In the setting of psychology and mindbuilding, the kernel instantiates persistent metacognition and high-throughput data/information/experience processing in a meaningful and deeply interesting representation.

# Purposes
The purposes of a kernel are: 
1. To augment `RI` with a robust set of rules for mutating its structure;
2. To create a core controller for communicating among;
	1. the internal structures of our mind (software);
	2. the external [systems/fields](<metapcms>) we seek to manipulate
		1. P: political/moral/analytical philosophy
		2. C: computer systems, computational models, mathematical models
		3. M: medicine
		4. S: systems: political institutions, social systems, biological systems, complex systems

# Definition
The **kernel** of `RI`, analogous to the executive control center of an operating system, will consist of the following elements:
1. *Process Management*: A set of operations, described formally or informally, over some subset of `RI` (where each subset consists of either notes or folders);
	1. where each operator in the kernel is defined by a name, a scope, and a rule set or pattern. The scope signifies the portion of `RI` over which the operator presides. The rule set or pattern signifies the behavior of the operator when applied to objects in its scope;
	2. operators need not be formally described; all that is needed for the rule set or pattern is some description of how the object is transformed by the operator.
2. *Resource Management*: A set of operations or notes that aids in accessing, storing, and navigating `RI`'s structure. Within `RI`, a 'resource' is either a folder or a file. An operation over these resources aids `Self` in navigating these files and folders. Also includes scripts for navigating `RI`'s structure.
3. *Integrity Management*: A set of operations or guidelines to preserve the general function, integrity, and security of `RI`, including the behavior of the kernel itself.
4. *Interrupt Handling*: A set of operations governing the interruption, switching, termination, and prioritization of tasks involving any component of `RI`. 
5. *I/O*: A set of operations managing the input to and output from `RI`.
