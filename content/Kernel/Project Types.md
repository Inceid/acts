# Definition 
A **project** is an external-facing entity requiring sustained work over a period of time. 

A **project type** is a general category for a project. 

# Typedef 
The following comprises a simple type system for projects. Our [Project Master](https://docs.google.com/spreadsheets/d/1TpseEbh22ZZirPF7BDOh3zI8w2nwoLGFc8mrtTdMNVQ/edit?gid=85980437#gid=85980437) follows this type system.

## Fields 
Fields are generic clusters of activity that share an academic discipline or overarching life theme. In this sense, projects are *extrinsically* categorized by the category an observer or specialist would assign them.

Each project can have only one of the following fields: 
- `med` medicine; 
- `meta` a meta-project or project that concerns either the self or the internal governance systems thereof (in my case, `RI` or *SS*).
- `cs` computer science; 
- `advo` advocacy; 
- `phil` a philosophy or political theory project; 
- `sys` a generic systems thinking project; 
- `pubh` public health; 

## Types 
A project may have any number of the following types. This serves as ain *intrinsic* category of the type of project it is, be it an essay, a piece of code, or position in an organization. In each case, the project type describes an aspect intrinsic to the project rather than its output. 

These are the types I use most often and refer to first when trying to categorize a project (and use in tagging these projects): 
- `anno` or `annotation` An [annotation](<Annotation.md>); 
- `prog` A program or piece of code; 
- `essay` An essay; 
- `RI` A [campaign](<Campaigns>) in `RI`;
- `n/a` uncategorized;

Other project types are listed below:
- `pos` A position;
- `cmte` A committee position; 
- `lit` A literature review; 
- `exam` An exam or test; 
- `lang` A language or language-like structure; 
- `sys` A concrete system.
